2. WHAT CADENCE DOES TO YOUR SYSTEM

You should understand these before you agree.

2.1 Reading controllers. Cadence reads the state of game controllers attached to your
computer, through XInput on Windows and through the kernel joystick interface on
Linux. It also queries Windows for the USB vendor and product identifiers of those
controllers so it can display the correct button names.

2.2 Sending input. The macro feature generates synthetic mouse and keyboard input,
which the operating system delivers to whichever window is focused. This only happens
while you have armed a macro and are pressing a controller button you bound to it.
Macros are disarmed every time Cadence starts.

2.3 A system-wide hotkey. Cadence registers one global hotkey, F8 by default, so that
macros can be stopped when Cadence is not the focused window. You can change which key
that is, and no other key is intercepted.

2.4 Update checks. On startup Cadence makes one HTTPS request to the GitHub releases
API to see whether a newer version exists. That request sends nothing about you beyond
what any HTTP request sends: your IP address and a user agent string naming the
application and its version. Nothing is downloaded or installed unless you click the
prompt and agree. You can prevent the check entirely by blocking the application in
your firewall.

2.5 What is not collected. Cadence contains no analytics, telemetry, advertising,
crash reporting or account system. It does not transmit your inputs, your timings,
your macros, your settings or any other information anywhere. Files it writes, such as
exported CSV logs, are written where you choose and stay there.
